## Optimization strategy and measured scope

The project uses normal `next dev`, `next build` and `next start`, with no configured static export or standalone output. Next14 includes a Squoosh fallback under `next/dist/server/lib/squoosh`; no additional package is needed for its image transforms. Built-in optimizer configuration and HTTP checks are recorded in image-optimization.md after the coordinated server restart.

Direct-transform evidence is in `image-transform-measurements.json`, generated by `measure-images.cjs`. At WebP quality75, workforce source209,622 bytes becomes22,816 bytes at640px and46,222 bytes at1080px. These are **encoded transfer-size measurements**, not Lighthouse, LCP or CPU improvements. Cold transforms took approximately250–952ms locally in that run, so caching matters. Mobile2×/3× displays may select larger srcset variants; do not claim every visitor receives the640px file.
